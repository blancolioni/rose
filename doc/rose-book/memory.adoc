= Memory

Each process runs in its own flat address space, starting at zero, divided into pages of 4096 bytes.
The memory manager, `mem`, decides what each page of each process holds, and maps it to physical memory when the process first uses it.
The mapping from virtual to physical pages is not persisted; what persists is the storage behind each page.

== Segments

A process's address space is made of _segments_.
A segment maps a range of virtual pages onto a region of storage from `store`, with flags that say whether the pages can be read, written or executed.

`elf` builds a process's segments when it launches the program:

* *Each loadable segment of the ELF executable* becomes a segment of the process.
** A read-only segment is mapped straight from the program's image.
   Every process running the program maps the same storage, and, once a page is in memory, the same physical page.
** A writable segment gets storage of its own: `elf` reserves a new region, copies the segment's contents from the image into it, and marks the segment _private_, so that its storage is released when the process is gone.
   The part of the segment beyond the contents of the file, such as `.bss`, reads as zeroes.
* *The stack* is a private, writable segment of 1 MB, which ends at `E000_0000`.

The run-time's heap is part of the program's `.bss`, so it has a fixed size.

== Page Faults

A process's pages are not mapped when it starts.
The first access to a page faults, and the kernel passes the fault to `mem`, which checks it against the process's segments.

* *An access that its segment does not allow*, or to an address outside every segment, is a protection fault, and stops the process.
* *A page of a read-only segment that is already in memory* is mapped to the same physical page, without reading storage.
  `mem` keeps these pages in a cache, and counts how many mappings each one has; a page that nothing maps stays cached until its memory is needed (#200).
* *Any other page* gets a free physical page, filled from the segment's region, or with zeroes if the segment has no region.
  If there is no free page, `mem` reclaims one; if it cannot, the process is stopped as out of memory.
* *A write to a page that is mapped read-only*, in a writable segment, makes the page writable and marks it dirty, so that the next checkpoint saves it (see <<Persistence>>).

`mem` gets physical memory from the kernel's memory map when it starts, and keeps track of which physical pages are free.

== Example

The `echo` command has three loadable segments.
When it runs, its address space is:

[#echo-memory]
.The address space of `echo`
[cols="2,2,2,5",options="header"]
|===
| Virtual address | Size | Access | Storage
| `0000_0000` | 48 KB | Read, execute | The code, from `echo`'s image, shared by every `echo` process
| `0000_D000` | 25 KB | Read | Constants, from the image, shared
| `0001_4000` | 105 KB | Read, write | Data and `.bss`, in a private region: the first page is copied from the image, and the rest reads as zeroes
| `DFF0_0000` | 1 MB | Read, write | The stack, in a private region
|===

The first time `echo` runs, each page it uses faults and is read from storage.
The next `echo` finds the pages of its code and constants already in memory, and maps them without reading storage; only its data and stack pages are new.
