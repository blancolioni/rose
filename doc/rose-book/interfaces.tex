\chapter{Interfaces}

Rose has two kinds of interface.

\begin{itemize}
    \item {\em IDL interfaces} are defined in the {\tt interfaces/} directory and implemented by servers.  Client and server packages are generated from the definitions.
    \item {\em Kernel capabilities} are implemented directly by the kernel.  They have no IDL definition; their endpoints are small integers fixed in the kernel source.
\end{itemize}

\section{Interface Identities}

Each IDL interface, and each operation in it, is identified by a 64-bit endpoint id.  The ids are recorded in {\tt interfaces/interfaces.txt}, as {\tt interface.{\em Name}\_Interface} for an interface and {\tt {\em Interface}.{\em Operation}} for an operation.

A server publishes an operation by creating an endpoint for its id with the meta capability (see Section \ref{sec:meta-interface}).  The kernel maps the 64-bit id to a small local endpoint index in the server's endpoint table, and that index is what an endpoint capability carries.

\subsection{Rose\_Interface}

Operations common to all interfaces.

\subsubsection{Operations}

\begin{itemize}
    \item \textbf{Destroy} Destroys the object associated with the capability.

    \begin{verbatim}

    \end{verbatim}
\end{itemize}

\subsection{Cap}

Operations on the object behind a capability.

\subsubsection{Operations}

\begin{itemize}
    \item \textbf{Destroy} Destroys the object associated with the capability.

    \begin{verbatim}
     procedure Destroy;
    \end{verbatim}

    \item \textbf{Get Object Id} Returns the object id of the object.

    \begin{verbatim}
     function Get_Object_Id return Object_Id;
    \end{verbatim}
\end{itemize}

\subsection{Cap\_Set}

A set of capabilities which can be referenced through a single capability.  Implemented by the {\tt caps} server.  A process's standard capabilities are supplied as a cap set (see Table \ref{table:standard-cap-env}).

\subsubsection{Operations}

\begin{itemize}
    \item \textbf{Append} Adds capabilities to the end of the set.

    \begin{verbatim}
     procedure Append
       (Caps : Capability_Array);
    \end{verbatim}

    \item \textbf{Get Cap} Returns the capability at the given index.

    \begin{verbatim}
     function Get_Cap
       (Index : Positive)
       return Capability;
    \end{verbatim}

    \item \textbf{Length} Returns the number of capabilities in the set.

    \begin{verbatim}
     function Length
       return Natural;
    \end{verbatim}
\end{itemize}

\subsection{Stream}

A stream which can be both read and written.

\subsubsection{Inherits}

\subsection{Launch}

Launching processes.

\subsubsection{Operations}

\begin{itemize}
    \item \textbf{Launch} Launches the process named by this capability.  The capabilities are copied to the new process, and the environment is placed in its environment page.  Arguments are passed as environment values {\tt @arg-count} and {\tt @arg01}, {\tt @arg02}, and so on.  Returns a capability for the Process interface of the new process.

    \begin{verbatim}
     function Launch
       (Caps        : Capability_Array;
        Environment : Storage_Array)
       return interface Process;
    \end{verbatim}
\end{itemize}

\subsection{Exec}

Installing executables.  Implemented by the {\tt exec} server.

\subsubsection{Inherits}

Launch

\subsubsection{Operations}

\begin{itemize}
    \item \textbf{Install} Installs an executable image read from a stream, and returns a launch capability for it.  {\tt Install\_Caps} are given to every process launched from the image.

    \begin{verbatim}
     function Install
       (Executable   : interface Stream_Reader;
        Name         : String;
        Install_Caps : Capability_Array)
       return interface Launch;
    \end{verbatim}
\end{itemize}

\subsection{Process}

A running process.  Implemented by the {\tt mem} server.

\subsubsection{Inherits}

\subsubsection{Operations}

\begin{itemize}

\subsection{Memory}

The memory manager interface, implemented by the {\tt mem} server.  The memory manager is told when a process is created, registers its segments, handles its page faults, and writes changed pages during a checkpoint.

\subsubsection{Operations}

\begin{itemize}
    \item \textbf{New Process} Creates the memory manager's record of a new process.

    \begin{verbatim}
     function New_Process
       (Process : interface Kernel_Process)
       return interface Process;
    \end{verbatim}

    \item \textbf{Register Process} Records the exec, text, data and stack ranges of a process, and its environment.

    \begin{verbatim}
     procedure Register_Process
       (Process     : interface Process;
        Exec_Base   : Word;
        Exec_Bound  : Word;
        Text_Base   : Word;
        Text_Bound  : Word;
        Data_Base   : Word;
        Data_Bound  : Word;
        Stack_Base  : Word;
        Stack_Bound : Word;
        Environment : Storage_Array);
    \end{verbatim}

    \item \textbf{Page Fault} Handles a page fault on behalf of the kernel.

    \begin{verbatim}
     procedure Page_Fault
       (Faulting_Object : Object_Id;
        Virtual_Page    : Word;
        Physical_Page   : Word;
        Action          : Page_Access_Type);
    \end{verbatim}

    \item \textbf{Take Physical Memory} Hands a range of physical memory to the caller.

    \begin{verbatim}
     procedure Take_Physical_Memory
       (Size   : Word;
        Start  : out Word;
        Amount : out Word);
    \end{verbatim}

    \item \textbf{Checkpoint} Writes every page changed since the last checkpoint, using the given capability to append each page to the log.

    \begin{verbatim}
     procedure Checkpoint
       (Append_Page : Capability);
    \end{verbatim}
\end{itemize}

\section{Kernel Capabilities}

These capabilities are implemented by the kernel.  The endpoint is the {\tt Endpoint} field of the capability layout, and parameters are passed in the invocation's data words.

\subsection{Meta}
\label{sec:meta-interface}

Every process has a meta capability.  It acts on the calling process: creating endpoints, receiving, deleting and rescinding the process's own capabilities, and exiting.

\begin{table}[ht]
\begin{tabular}{l l l}
\hline\hline
Endpoint & Name & Description \\ [0.5ex]
\hline
1  & Create Endpoint & $data_0$, $data_1$: 64-bit endpoint id; \\
   &                 & $data_2$ (optional): identifier. \\
   &                 & Returns a receive cap and/or an endpoint cap \\
9  & Get Object Id   & Returns the object id in the cap's payload \\
17 & Receive on any  & Wait for a message on any endpoint \\
28 & Kernel debug    & $data_1 \neq 0$ enables invocation logging \\
29 & Rescind         & Rescinds each sent cap \\
30 & Delete          & Deletes each sent cap from the caller's table \\
31 & Exit            & Ends the calling process \\
\hline
\end{tabular}
\caption{Meta capability endpoints}
\label{table:meta_interface}
\end{table}

Endpoint 1 returns a receive capability if the endpoint id is zero, or if the caller asks to receive more than one capability.  It returns an endpoint capability if the endpoint id is not zero.  The identifier is stored in the endpoint capability and passed to the server with every invocation, which lets one endpoint serve many objects.

The kernel source also reserves endpoints 2 (create entry cap), 3 (create page object cap), 4 (create send cap), 5 (create singleton receive), 6 (create cap set), 7 (add cap to set), 8 (remove cap from set) and 16 (receive on caps), but these are not implemented.  Invoking them returns {\tt Invalid\_Endpoint}.  Cap sets are provided by the {\tt caps} server instead.

\subsection{Create}

Turns four data words into a capability layout and returns a new capability with that layout.  The kernel gives this capability to {\em init} only.  It can forge any capability, and is due to be removed (issue \#115).

\begin{verbatim}
     function Create_Capability
       (Header_1, Header_2, Payload_Low, Payload_High : Word_32)
       return Capability;
\end{verbatim}

\subsection{Copy}

The payload is a process object id.  Copies one of that process's endpoint capabilities into the caller's table.

\begin{itemize}
    \item $data_0$, $data_1$: the 64-bit endpoint id to copy.
    \item $data_2$ (optional): a new identifier for the copied capability.
\end{itemize}

Returns the copied capability, or {\tt Invalid\_Endpoint} if the process has no such endpoint.

\subsection{Boot}

Launches a boot module.  Used only by {\em init}.

\begin{itemize}
    \item $data_0$: the module index.
    \item $data_1$: the process priority.
    \item $data_2$ onwards (optional): arguments, set in the new process's environment as {\tt @arg-count} and {\tt @arg01}, {\tt @arg02}, and so on.
    \item Sent capabilities are copied to the new process.
\end{itemize}

Returns the object id of the new process.
