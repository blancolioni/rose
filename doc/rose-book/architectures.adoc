= Architecture Specifics

== i686

=== Invocation Record

A process passes its invocation record to the kernel by address, not in registers.
`Rose.System_Calls.Enter_Kernel` jumps to the system call page at `FFFF_0000`, with the address of the record on the stack, and the page enters the kernel with `sysenter` (`src/asm/i686/mp.s`).

[#i686-invocation]
.i686 registers on a system call
[cols="1,4",options="header"]
|===
| Register | Use
| `eax` | The address of the invocation record, in the caller's memory
| `ecx` | The caller's stack pointer, for `sysexit`
| `edx` | The return address in the system call page, for `sysexit`
| `ebx`, `esi`, `edi`, `ebp` | Saved, and restored when the process resumes
|===

The kernel copies in the first two words of the record, the control word and the capability, and then what the control word says was sent: the words up to `SW` if `Send_Words` is set, the capabilities up to `SC` if `Send_Caps` is set, and the buffer's address and length if `Send_Buffer` or `Writable_Buffer` is set (#892).
It never reads the caller's `Reply Capability`, `Endpoint Id` or `Identifier`.
When it resumes the process with a reply, it copies out the six header words, which it writes on every delivery, and what the reply sent, to the same address, past any write protection, which is why the kernel first copies a page that a checkpoint has yet to save (see <<Checkpoint Mode>>).
The copy reads the flags and counts by their bit positions, which the representation clause of `Rose.Invocation.Control_Word` fixes; `mp.s` names the same positions.

Passing words 0 and 1 in registers, which are free on `sysenter`, would save the copy and the validity check for calls that need nothing else.
It isn't done: #698 found it not worth the change to the system call page.
Copying only what was sent made a call that the kernel answers itself about 11% faster in QEMU, and a round trip to another process about 1% faster.

=== Page Table

Uses 4K pages.
Per-process virtual memory is 3G.
Page object ids are 64 bits on every architecture: the top byte is `FF`, and the low 56 bits are the page (see <<Persistence>>).
