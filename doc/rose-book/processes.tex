\chapter{Processes}

A process is named by a launch capability.  Invoking the capability executes the process.

Object ids in the range $1$ to $2^{24} - 1$ represent processes.

Process id 1 is used to refer to the Kernel.

\section{Standard Launch Sequence}

The {\em launch} capability invokes the {\em exec} server, which holds an {\em Executable} capability.  
The {\em Launch} method on this capability invokes the {\em elf} server,
which invokes a kernel capability for creating a new process, returning a {\em Process} and a start capability.
The {\em mem} server is invoked, which returns a {\em Process\_Memory} capability.
This is used to load the ELF image from storage.

\section{Example}

Consider the following excerpt from a shell session:

{\tt user\$ cat readme.txt }

A launch capability for the {\tt cat} program is found in the shell's environment.  A new environment is created, setting environment capabilities for input/output streams.  The argument is interpreted as the name of a file, a {\tt stream-reader} capability to this file is added to the environment.

\section{Environment}

The environment is supplied as a table of entries starting at a known address.

\section{Segments}

A process consists of several segments; generally code, text, data, stack, and heap.  The code and text segments have statically allocated continguous regions, and are shared amongst all processes which use the same image.  The data and stack segments use separate contiguous regions for each process.  The heap segment uses a dynamic non-contiguous region.

\begin{tabular}{l l l l}

Data & R W & Dynamic & Contiguous \\
Stack & R W & Dynamic & Contiguous \\
Heap & R W E & Dynamic & Non-contiguous \\
\hline
\end{tabular}
\caption{Standard process segments}
\label{table:standard-process-segments}
\end{table}

\subsection{Contiguous Regions}

For segments whose size does not change over time, a contiguous region is allocated.

\subsection{The Heap Segment}

The mapping between heap addresses and the underlying region is similar to the page mapping of virtual memory.  The top level directory points to 512 pages, each of which contains 512 object ids, which are first object ids of a region range.  The number of objects in the range is defined at system initialisation.  A small system might use 1 region object, which leads to a total addressable heap page count of $2^{18}$, 262 144, or a gigabyte if 4K pages are used.  If the range is 4K, 4 terabytes are available to each process.
